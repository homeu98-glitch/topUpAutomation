**結論（code 層）：唔可能係 Supabase 觸發。**
- `supabase/` 3 個 SQL：zero trigger 踫 `transactions` 表；唯一 trigger 係 `trg_refresh_mpaybackoffice_match_index`（維護 mPay match index）。冇 pg_cron、冇 Edge Function。
- `shops.auto_approve_enabled` schema 預設 `false`。
- 全 repo 唯一寫 `status='approved'` 嘅地方：`lib/topup-service.js` `updateTransactionsStatus()`，只由 `approveTransaction()` 呼叫。

**自動批唯一機制**：`runAutoApprovalSweep()`，三個入口，全部只批 DB `auto_approve_enabled = true` 嘅店：
1. Vercel cron `/api/cron/auto-approve`（vercel.json：`0 0 * * *` UTC = 澳門 08:00）
2. Admin「立即執行自動核准」→ `/api/admin/auto-approve-sweep`（admin session）
3. Owner「立即執行」→ `/api/owner/auto-approve-sweep`（owner session）

**approved_by 判讀**（sweep 用 `shop.owner_login || "auto-approve"` 記賬）：
- 「管理員 xxxxx」= admin 手動批
- 店主 code（如 60000000）= auto sweep **或** 店主手動批（兩者記賬一樣，要靠 approved_at / last_auto_approved_at 區分）

**隐患（admin.js）**：
- L912：auto-approve 對話框冇選特定店（bulk 模式）按「儲存」→ 送 `autoApproveEnabled: true` 去 `/api/admin/bulk-shop-settings`，而 bulk 列表預設全選所有店（L443）⇒ 一次誤撳開曬所有店 auto。
- sweep 讀 DB 欄位唔讀 UI 狀態 ⇒「UI 顯示冇開」≠「DB 冇開」。
